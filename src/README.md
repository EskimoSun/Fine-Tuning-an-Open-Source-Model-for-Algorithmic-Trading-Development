# qc_eval

Evaluation harness for LEAN code generated by LLMs (QuantConnect capstone).

For prompt-first 1–5 scoring plus gold-template trade/timing/DTW comparisons of
existing Qwen generations, see [SCORING.md](SCORING.md). Run
`python -m qc_eval.score --help` from this directory.

The agreed Excel deliverable is [QC_Eval_Prompt_Error_Sheet.xlsx](QC_Eval_Prompt_Error_Sheet.xlsx).
It retains `Legend / Results / Summary` and the original 100-prompt model layout.
`QC Feedback` reports repaired candidates separately; `Judge Details` contains the
eight-dimensional evidence. See [Excel output](SCORING.md#excel-output) to refresh
the English workbook from the published snapshot without API calls.

## What works now (no QC access needed)

- `prompts.jsonl`: 25 benchmark prompts across equities, portfolio,
  universe selection, options, futures, forex/crypto, order events,
  lookahead traps, research, and abstention. Each has a `must_contain`
  checklist for prompt adherence and a `targets` note on which failure
  mode it probes.
- `qc_eval/static_checks.py`: parse check, algorithm structure, legacy
  PascalCase API, unknown `self.` methods (possible hallucinations),
  indicator ready checks, lookahead heuristics, prompt adherence.
- `qc_eval/taxonomy.py`: the shared error categories every check reports.
- `qc_eval/run_eval.py`: scores a JSONL of generations, writes a CSV,
  prints per-model pass rates with 95% bootstrap intervals and error counts.

## What needs QC keys

- `qc_eval/qc_client.py`: compile and backtest on QuantConnect cloud.
  Auth follows QC's docs; endpoint field names are **unverified** until
  we test against the live API. Check auth first:
  `QC_USER_ID=... QC_API_TOKEN=... python -m qc_eval.qc_client`

## Usage

```bash
pip install requests
python -m qc_eval.run_eval examples/demo_generations.jsonl            # static only
python -m qc_eval.run_eval generations.jsonl --backtest               # + QC cloud
```

Generation file format, one line per output:
`{"prompt_id": "eq_sma_cross", "model": "qwen2.5-coder-7b", "output": "<raw model text>"}`

## Known limits

- Static warnings are heuristics. `UNKNOWN_API` uses an incomplete list of
  LEAN methods, and `LOOKAHEAD_SUSPECT` flags every `.shift(-n)`, including
  legitimate ones like building a next-day training label from past data.
  Hand-check warnings before counting them as errors.
- Static pass does not mean correct. Hallucinated methods are only warnings
  here; the compile step catches them.
- Abstention prompts pass only if the model declines (phrase match). Check a
  sample by hand.
- No behavioral match against reference code yet; that needs gold
  implementations and an agreed trade tolerance.
- 25 prompts gives wide intervals (about ±20 points at 50%). Use it to find
  failure modes, not to rank close models.

## Full pipeline (100-prompt baseline)

`data/prompts_100.jsonl` has 10 of QuantConnect's own project templates x 10 prompts:
3 customer segments (individual, startup, institutional) x 3 specificity levels
(vague, precise, over_specified), plus one ceiling prompt per template. The
Summary tab breaks results out by segment and by specificity.
Templates come from https://github.com/QuantConnect/Documentation/tree/master/project-templates
(Apache 2.0); each template's `main.py` is copied to `data/templates/` as a
human-written reference alongside Fable's. The 100 prompts were written by
Claude Fable 5.1 on Oct 15, 2026 (see data/build_prompts.py); prompt text follows
each template's code, not its description. `qc_eval/pipeline.py`
generates code with each model, compiles and backtests it on QuantConnect, has
Fable score fidelity to the prompt, and writes everything into
`QC_Eval_Prompt_Error_Sheet.xlsx`.

```bash
export ANTHROPIC_API_KEY=...              # Fable: references + judge
export QWEN_BASE_URL=https://api.together.xyz/v1 QWEN_API_KEY=...
export QWEN_BASE_MODEL=Qwen/Qwen3-4B-Instruct-2507   # check the exact id on your endpoint
export QC_USER_ID=... QC_API_TOKEN=...

python -m qc_eval.pipeline --models fable --limit 5        # smoke test first
python -m qc_eval.pipeline --models fable,qwen_base        # baseline
# after fine-tuning:
export QWEN_TUNED_MODEL=...
python -m qc_eval.pipeline --models qwen_tuned
```

Generations are cached in `runs/<model>/<prompt_id>.json` with the model id and
timestamp, so reruns score the same outputs. Pass `--regenerate` for fresh ones.
`--mock --no-qc` runs the plumbing offline.

Before trusting the Qwen numbers, check the Fable column: any prompt where
Fable's own reference fails to compile or run is a bad prompt or a broken
template. Fix or drop it before comparing Qwen.
